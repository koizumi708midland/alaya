操作マニュアル

文書解析アシスタント（仮名化AI解析基盤）

このアシスタントは、顧問先の資料を生成AIで分析するとき、実名をAIに渡さないための仕組みです。 氏名・住所・法人名などを記号に置き換え、人が確認して承認したうえで、記号のままAIに渡します。 結果は、人が読む直前に実名へ戻します。
操作はすべて Google Chat の中で行います。
目次
  • 1. 全体の流れ

1全体の流れ

ひとつの案件は、次の順に進みます。担当者が触れるのは Google Chat だけです。

  1. 資料を渡す：案件フォルダに資料を置き、その URL をアシスタントに送る
  2. 承認する：仮名化の結果（どの語が何に置き換わったか）を確認し、承認する
  3. 分析する：操作パネルのボタンで、診断・設計・提案・点検を行う
  4. 受け取る：成果物が Drive に保存される（実名に戻っている）
承認するまで、情報はAIに渡りません。承認は人が行います。

2資料を依頼する

  1. 案件フォルダ、またはその中のサブフォルダに、資料を置く
  2. 資料の URL をコピーする
  3. 案件スペースで @文書解析アシスタント に続けて URL を貼り、送信する
  4. 「資料を受け取りました」と応答が返る（この時点では、まだAIに渡っていない）

複数の資料を送るときは、応答を待たずに続けて送れます。ただし1件ずつ承認してください。

医療費の領収書・診断書・処方箋は扱えません。これらは要配慮個人情報にあたるため、ファイル名に「医療費」「診療」などの語があると、受け付けを断ります。

3承認する（最も大切な工程）

仮名化が終わると、承認カードが届きます。ここが、この仕組みの要です。

突合表を確認する

カードには、どの語が何に置き換わったかの一覧（突合表）が表示されます。次の2点を確認してください。

観点確認すること見つかったら
漏れ置き換えるべき実名が、そのまま残っていないか差し戻して報告する
過剰置き換えなくてよい語まで置き換えていないか承認してよい。ただし報告する
  1. 突合表をスクロールして、実名の残りがないか確認する
  2. 問題なければ「承認」を押す。AIに渡ってよい状態になる
  3. 漏れがあれば「差し戻し」を押す。AIには渡らない
誰がいつ承認したかは、記録に残ります。

4分析する

@文書解析アシスタント パネル と送ると、操作パネルが開きます。工程に応じてボタンを押します。

ボタンすること必要な資料
案件を始める顧問先名・会計期間・フォルダを登録—
診断を始める現状を診断し、質問票を作る仕訳帳
設計の前提を確認する設計に必要な確認事項をまとめる仕訳帳＋診断の回答
経理設計図を作る現状と改善後の業務の流れを作る上記＋設計の回答
提案書を作る顧問先向けの提案書を作る経理設計図
仕訳監査仕訳帳を点検する仕訳帳

成果物は、案件フォルダの「成果物」に保存されます。氏名・法人名は実名に戻っています。

5質問票に回答する

  1. 「成果物」フォルダの質問票（Google ドキュメント）を開く
  2. 回答欄に記入する。確認事項はチェックボックスに印を付ける
  3. 文書の URL をコピーし、アシスタントに送る
  4. 承認する。回答が読み取られ、次の工程に反映される

6誤りを報告する

仮名化の漏れや、分析・点検の誤りに気づいたら、その場で報告できます。報告は、判断の基準（モジュール）を良くするために使われます。

  1. パネルの「誤りを報告」を押す
  2. 報告の種類を選ぶ（仮名化の漏れ、分析の誤り、など）
  3. 対象（依頼ID・項目IDなど）と、どこが何が誤っているかを書く
  4. 「報告する」を押す
報告に実名は書かないでください。「3行目の法人名」のように位置で示します。書いてしまっても、案件の対応表にある実名は、保存の前に記号へ置き換えられます。

7やってはいけないこと

  • 承認カードを確認せずに承認すること
  • この仕組みを介さずに、個人で契約したAIへ顧問先の情報を入力すること
  • 医療費の領収書など、要配慮個人情報を含む資料を投入すること
  • 成果物を確認せずに、そのまま顧問先へ提出すること（AIの出力には誤りが含まれることがあります）

8困ったとき

症状対応
アシスタントが応答しない数分待って、もう一度送る
「案件として登録されていません」と出る管理者に案件の登録を依頼する
エラーが表示された文言を控えて、事務所の管理者に伝える
誤った資料を投入した承認前なら差し戻す。承認後ならすぐ管理者に連絡する
